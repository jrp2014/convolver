### Audacity failure: editor state does not reach export

1. Set Audacity Audio settings > Default sample rate to 48000 Hz; restart it and open the 48 kHz stereo test project.
2. Play once. Log verifies instance #1 starts at 48000 Hz, 2 in/2 out. Open its vendor editor, which now also shows host 48000 Hz.
3. Choose `package/presets/echo-48000-stereo/filter.cfg`. Editor shows filter.cfg, Active, length 5.4 ms; Gain 0, Mix 100%, Bypass off. Log records successful request 2.
4. Save an Audacity preset as `preview-0.12.8-echo-choose`, then save the project with Command-S.
5. Export full project, stereo 48000 Hz, 32-bit float, to `audacity-echo-choose.wav`.
6. Export instance #3 logs `Loaded a saved project or preset with no filter`, then `No filter, so audio passes unchanged`.
7. CLI comparison FAILS against echo (maximum error 0.0625), but PASSES against identity/unfiltered reference (maximum error 5.22e-08).

The mismatch is wrong processing state, not a latency offset. The exact code-level cause has not been established. Check the editor's asynchronous file-load notification/state propagation into Audacity's stored effect settings and separate render instance. A fix should reproduce this sequence and verify both exports and project/preset restoration.

Before the instance had played, Choose used 44100 Hz even after changing the default preference. Restarting and playing at 48000 Hz allowed loading. This setup detail must be kept distinct from the export-state failure.
