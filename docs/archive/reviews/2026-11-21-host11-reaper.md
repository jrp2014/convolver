## REAPER passed all 8 checks on 21 November 2026 at 16:19

The stereo preset loaded, the filter survived a full quit and reopen, and
both renders matched the reference. Both REAPER processes quit on their
own. No dialog needed an answer.

### Build and host

I used `candidate-macos-arm64` from run `44904627283`. The manifest
identified source commit `4d78868772b5689cc7c228b4b3c26e865734064a`, and
the CLI and installed VST3 both reported **0.16.14**. The installed user
bundle matched the candidate byte for byte. There was no system-wide
Convolver VST3. REAPER 7.86 ran on macOS 27.2.1 arm64 with CoreAudio
already at **48,000 Hz**, using 512-frame blocks.
[Candidate run](https://github.com/jrp2014/convolver/actions/runs/44904627283)

**One finding for the next script revision:** both readings labelled
“while playing” recorded `play_state: 0` (stopped). The input clip lasts
85 ms and the script samples status after 1.5 seconds. To verify the
status *during* playback, the script needs to capture it while REAPER
reports a running transport. The two render comparisons and the filter
restoration were verified independently of that reading.
