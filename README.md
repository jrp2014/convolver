# Convolver

Convolver applies finite impulse response (FIR) filters to multichannel audio. Typical
uses are digital room correction, crossovers and routing or mixing channels, for
example applying filters generated by DRC, REW or Audiolense to music files or a
live stream.

It runs on macOS, Linux and Windows and comes in three forms:

- a **command-line tool** that filters WAV files or raw audio streams
- a **VST3 plug-in** for digital audio workstations (DAWs) and other plug-in hosts
- a **C++20 library** you can build into your own program

Supply a multichannel impulse-response (IR) sound file or a Convolver **`.cfg`**
file describing filters and routes. Convolver applies filters; it does not
measure your room or design them. Other programs use variants of the configuration
format, so [compatibility is not universal](docs/configuration-compatibility.md).

New to the project? Use the [documentation index](docs/README.md), or start with
[the audio concepts](docs/concepts.md). Open work is tracked in [TODO.md](TODO.md).

## Build and try it

You need CMake 3.20 or later, a C++20 compiler, FFTW (single precision) and
libsndfile. The default test build also needs Python 3.8 or later.

```sh
# macOS (Homebrew)
brew install cmake fftw libsndfile
# Debian or Ubuntu
sudo apt-get install cmake g++ python3 libfftw3-dev libsndfile1-dev
```

Then, from the repository root:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/convolver --version
```

If Clang is your default compiler on Linux, the default build also runs the
historical regression tests, which need Clang's sanitizer runtimes. When the
first command stops with "Clang with ASan/UBSan runtimes is required for legacy
tests", install them (on Ubuntu, `libclang-rt-18-dev` for Clang 18) or add
`-DCONVOLVER_LEGACY_TESTS=OFF`.

On a Mac you can use Apple's Accelerate framework instead of FFTW by adding
`-DCONVOLVER_FFT_BACKEND=ACCELERATE` to the first command. On any platform,
`-DCONVOLVER_FFT_BACKEND=OOURA` builds a small FFT into the library so FFTW is not
needed. Windows builds use vcpkg; see the
[portable guide](docs/portable-core.md#windows-build).

## Filter a file

With a multichannel impulse response, each IR channel filters the matching
input channel:

```sh
./build/convolver --filter impulse.wav --input music.wav --output corrected.wav
```

With a configuration file:

```sh
./build/convolver --filter room.cfg --input music.wav --output corrected.wav --output-format wav-pcm24
```

Output is 32-bit float WAV unless you choose `wav-pcm8`, `wav-pcm16`,
`wav-pcm24`, `wav-pcm32` or `raw-float`; integer formats can add `--dither` and
`--noise-shaping`. Use `--gain-db -3` to lower the level by 3 dB; positive
values raise it. Automatic attenuation options and their assumptions are in
[the CLI reference](docs/portable-core.md#gain-and-attenuation).
The output keeps the whole filter tail, and Convolver's
processing delay is removed, so the result lines up with the input. The input
sample rate and channel count must match the filter; Convolver does not resample.

To filter a live stream, pipe raw 32-bit float audio through it:

```sh
producer | ./build/convolver --filter room.cfg --input - --raw-input 48000 2 \
  --output - --output-format raw-float | consumer
```

Run `./build/convolver --help` for every option.

## Configuration files

A `.cfg` file names the sample rate and channel counts, per-channel delays,
and one or more paths from input channels through IRs to output channels.
The [current configuration reference](docs/configuration.md) includes a complete
stereo example, route-number explanations and troubleshooting.

```sh
./build/convolver --validate room.cfg
./build/convolver --inspect room.cfg
```

`--inspect` shows the selected configuration, routing, latency and filter length;
add `--json` for machine-readable output. Paths are relative to the configuration
that contains them. A list of configurations can select a filter matching the
input rate and channel count.

## VST3 plug-in

The plug-in is optional and needs the Steinberg VST3 SDK, fetched separately.
It takes up to 8 input and 8 output channels, and the counts may differ.
Filters are loaded through the host's preset menu: a small tool converts a WAV
or `.cfg` file into a `.vstpreset`. See the [VST3 guide](docs/vst3.md).

## About this project

> Convolver began in 2005 as a set of Windows applications by JRP: a Windows
> Media Player plug-in, a DirectShow filter, a VST 2 plug-in and command-line
> tools, released on SourceForge up to version 4.4. The project's original
> website and documentation are still at
> [convolver.sourceforge.net](https://convolver.sourceforge.net/), and its
> releases at
> [sourceforge.net/projects/convolver](https://sourceforge.net/projects/convolver/).
> That documentation describes the historical Windows applications, not the
> portable version in this repository.

The historical source is preserved in [`historical/`](historical/) but is not
built by this project, and an archived copy of the 4.4 website is in
[`docs/historical/`](docs/historical/convolver-4.4/README.md). The
[history page](docs/history.md) explains where the code came from, how the
portable implementation replaced it and
[how the two differ](docs/history.md#how-the-portable-version-differs).
