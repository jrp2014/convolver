# VST3-27

## Fixed

- VST3: a late pairing message can no longer connect the plug-in's controls
  to another instance of Convolver. When a host that passes messages late
  moved the controller from one instance to another, the first instance's
  delayed message could pair the controller with it again, so a later
  Latency, Gain mode, Gain, Mix, Bypass or chosen file went to that instance
  and changed what it saved, while the instance on screen kept its old
  settings (VST3-27, found by jrp's review of 25 November 2026 in the test
  harness; whether a shipping host delivers that sequence is unknown). The
  controller now pairs only with the answer to its current connection. No
  change to the sound or to saved projects. See the
  [adapter contract](../docs/develop/plugin-contract.md#status-and-log).

## For contributors

- VST3 (VST3-27): the controller numbers each connection
  (`Bridges::stamp()`), starts it unpaired and sends the number in
  `ConvolverPairRequest`; the processor answers with its key and the number
  in `ConvolverPair`, and sends nothing from `connect()` until a request has
  come. The controller refuses an answer whose number is not its current
  connection's, and every answer while disconnected. `vst3.adapter`
  `pairing_follows_connection` checks jrp's two-instance sequence and five
  variants through delaying proxies; on `main` before the fix it failed
  ("a late pairing message from A changed the controller's Latency").
