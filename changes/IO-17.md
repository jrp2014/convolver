# IO-17

## Fixed

- Command line (IO-17): a filter from a pipe named by a path, such as
  `--filter <(cat room.cfg)` or `/dev/stdin` fed by a pipe, is now read whole
  into a temporary file and loaded from there, so a configuration, a
  configuration list, a FLAC IR and an IR that plays on each channel or as
  true stereo all load as they would from a file; before, they were refused
  with misleading messages, such as a header line with too few values or an
  empty configuration. A configuration from a pipe must name its IR files
  with full paths, and one with a relative name says that the pipe is the
  reason. An input from a pipe that libsndfile cannot read without going
  back in the file, such as FLAC, now says that the pipe is the reason and
  what to send instead, and `--inspect` or `--validate` adds a note when a
  filter from a pipe fails. On macOS, a file redirected to `/dev/stdin` is
  read by its own path. See
  [input files](../docs/use/command-line.md#input-files).

## For contributors

- Tests (IO-17): `native.cli` loads a mono IR on a stereo input, a `.cfg`
  naming its IR by full path, a configuration list and a FLAC IR from a
  pipe's `/dev/fd/N`, each checked against the same file read from disk,
  with the temporary copy removed afterwards; checks that a relative IR name
  in a piped `.cfg` and a FLAC input on a pipe are refused with the pipe
  named as the reason, and that `--inspect` of a piped `.cfg` notes the
  pipe; and filters a WAV file redirected to `/dev/stdin` as the input and
  as the filter. `cli::is_stream()` (inspection_cli.cpp) tells a pipe,
  socket or device from a file for both the renderer and `--inspect`.
