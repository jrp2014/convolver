# IO-13

## Fixed

- Command-line tools on Windows (IO-13): when a write fails because the
  path is too long for Windows (a file's full path over 259 characters, a
  folder's over 247), `convolver`, `convolver-preset` and
  `convolver-equalizer-apo` now say so and give the path's length. Until
  now they said the folder exists but could not be written, which sent
  people to its permissions. See
  [output safety](../docs/use/command-line.md#output-safety).

## For contributors

- Tools (IO-13): `windows_path_length_problem()` and
  `windows_path_length_fix` in `portable/utf8.hpp` give the cause and the
  fix, and are consulted only after a write has failed: by the sound-file
  writer (`open_or_throw()` in `portable/io.cpp`), by `convolver-preset`
  (for an LV2 preset, its folder and both files) and by
  `convolver-equalizer-apo` (its folder, its impulse responses through the
  sound-file writer, and `convolver.txt`). The tools do not declare
  themselves long-path aware, so Windows refuses such paths even where long
  paths are turned on. Tests, run only on Windows (by CI): `native.cli`,
  `plugins.presets` and `export.equalizer_apo` write to paths over the
  limits and accept either the file written or a refusal that names the
  length and not the folder's permissions; the Equalizer APO case covers a
  folder too long and a folder that fits holding files that do not.
