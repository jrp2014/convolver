# IO-16

## Fixed

- Command line (IO-16): an input or filter given as a pipe's path, such as
  the shell's `<(command)` or `/dev/stdin` fed by a pipe, is read again on
  Linux instead of stopping with "filesystem error: cannot make canonical
  path". A path such as `/dev/stdin` that leads to the output's own file is
  still refused. See [output safety](../docs/use/command-line.md#output-safety).

## For contributors

- Tests (IO-16): `native.cli` filters a WAV piped to `/dev/stdin`, and a WAV
  input and a WAV filter on a pipe's `/dev/fd/N`, checking each output
  against the same files read from disk, and checks that `/dev/stdin`
  redirected from the output's own file is refused and left untouched. The
  output check compares files by identity first and treats a path with no
  canonical form as different; the configuration loader identifies such a
  path by its absolute path.
