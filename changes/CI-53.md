# CI-53, CI-54, DOC-21

## For contributors

- CI (CI-53): a later push to a pull request runs only the workflows that
  the files changed since that workflow's last full passed run need,
  counting what has landed on `main` since that run tested against it; the
  `scope` job names the run whose result stands. On `main`, a merge that
  changes anything but documentation still runs everything; one that
  changes only documentation runs Lint. Every release and preview gets the
  full CI: the draft-release workflow refuses a tag on which the native,
  VST3, LV2, Audio Unit, fuzz and Lint workflows have not passed when
  started by hand. See
  [drafts and later pushes](../docs/develop/testing.md#drafts-and-later-pushes).
- CI (CI-54): a draft pull request runs Lint and the Linux jobs only;
  marking it ready, or starting the workflows by hand on the branch, runs
  macOS and Windows.
- Process (DOC-21): fewer pushes and review rounds for simple changes.
  Merge `main` into a branch only on a conflict or when jrp asks; answer a
  review round in one push and never push only to record a pull request
  number; an independent review is needed only for code, DSP, plug-in,
  saved-state, `.cfg` and release changes, and its wording findings never
  block or start another round; a ready pull request's handoff note keeps
  only its State line; the status page changes only at milestones. See
  [while working](../docs/develop/workflow.md#while-working).

## Decisions: Documentation

- **21 November 2026.** Simple changes take fewer CI runs and review rounds
  (DOC-21, CI-53, CI-54), from a count of that day's pull requests: a later
  push runs only what changed since the last full run that passed; a draft
  runs Lint and the Linux jobs; `main` is merged into a branch only on a
  conflict or on request; a review round is answered in one push; an
  independent review is needed only for code, DSP, plug-in, saved-state,
  `.cfg` and release changes, and wording findings never block; a ready pull
  request's handoff note keeps only its State; the status page changes only
  at milestones. jrp kept two safeguards: every release and preview gets the
  full CI, and `main` keeps the full post-merge run whenever a merge changes
  code or tests ("keep the full post merge ci as now, when there have been
  code or test changes"); he chose that over skipping post-merge runs whose
  code a pull request had already tested. On 23 November, after his review
  found a documentation push carrying a result tested against an earlier
  `main`, he chose to count what has landed on `main` since the earlier run
  as changed before a pull request carries a result. See
  [while working](../docs/develop/workflow.md#while-working) and
  [CI triggers](../docs/develop/testing.md#drafts-and-later-pushes).
