# IO-12

## Fixed

- Sound files (IO-12): a W64 (Wave64) file whose header uses the extended
  format with 32- or 64-bit float samples, as FFmpeg writes `pcm_f32le` and
  `pcm_f64le` audio to a `.w64` file, now plays its own samples. libsndfile
  1.2.2 decodes such samples as integers, so a filter holding 1.0 and 0.0
  played as 0.496 and 0.0, and every other value was just as wrong (0.5 as
  0.492), with no message, as `--input`, as a filter and in the plug-ins;
  the 64-bit form did not open at all. Such a file with A-law, µ-law or any
  other samples that are neither PCM nor 32- or 64-bit float is now refused
  with advice instead of being read as noise. See
  [input files](../docs/use/command-line.md#input-files).

## For contributors

- Sound files (IO-12): `extensible_wave64_float()` (`sound_files.cpp`)
  finds where such a file's samples are, and `open_stored_samples()`
  decodes them with `decode_raw()`, needing no sound-file library. The
  libsndfile reader (`AudioReader`, and so every filter and `--input`) and
  the AudioToolbox reader both use them, so the two read such a file the
  same way whatever either library makes of it; the AudioToolbox reader's
  headerless files use the same class, which replaces its own `RawFile`.
  The Wave64 chunk walk is shared with the B-format check. Tests:
  `native.io` reads eight hand-made files (`tests/native/wave64.hpp`) as
  filters and as input, among them jrp's two-sample file, 64-bit and
  stereo float, audio followed by another chunk, PCM left to libsndfile,
  and three refusals; `native.audio_toolbox` (macOS) requires the same
  samples and refusals from both readers. The B-format Wave64 fixture now
  holds float samples, like the others.
